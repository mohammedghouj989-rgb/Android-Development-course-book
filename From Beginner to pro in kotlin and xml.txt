Chapter 1: Variables, Data Types, and Operators
Every program you write needs to remember information. In programming, we store information in containers called Variables.

1.1 What is a Variable? (The Box Analogy)
Think of a variable as a labeled storage box in your room:
- The label on the box is the variable name.
- The stuff inside the box is the value.
In Kotlin, we create variables using two special keywords: val and var.

1.2 val vs var (Immutable vs Mutable)
- val (Value): A read-only box. Once you store a value, it cannot be changed. Use val by default for safety.
- var (Variable): A mutable box. You can change its value anytime during execution.

1.3 Kotlin's Core Data Types
Kotlin is statically typed and recognizes these primary types:
- Int: Whole numbers (val score = 100)
- Double / Float: Decimals (val pi = 3.14)
- Boolean: True or False states (val isActive = true)
- String: Text sentences (val name = "Mohammed")
- Char: Single characters (val grade = 'A')

1.4 Code Example & Execution
fun main() {
    val playerName: String = "Mohammed"
    var score: Int = 10
    score = score + 15 // score is now 25
    
    println("Player: $playerName, Score: $score")
}
* Explanation: main() is the app entry point. val locks the name, while var allows modifying the score. The $ symbol performs String Interpolation to insert variable values directly into text.

Chapter 2: Control Flow (If/Else, When, Loops)
--------------------------------------------------
Programs make decisions and repeat tasks using control flow structures.

2.1 Conditional Branching (if, else, when)
fun main() {
    val health = 45
    
    // If/Else branching
    if (health <= 0) {
        println("Game Over")
    } else if (health < 50) {
        println("Warning: Low Health!")
    } else {
        println("Healthy")
    }

    // When expression (Supercharged Switch)
    val weapon = "Sword"
    when (weapon) {
        "Sword" -> println("Melee Attack!")
        "Bow" -> println("Ranged Attack!")
        else -> println("Unarmed")
    }
}

2.2 Loops (for and while)
fun main() {
    // For loop range
    for (i in 1..3) {
        println("Wave $i incoming...")
    }

    // While loop
    var countdown = 3
    while (countdown > 0) {
        println("T-minus $countdown")
        countdown--
    }
}

Chapter 3: Functions and Null Safety
--------------------------------------------------
Functions break code into reusable blocks, and Null Safety prevents application crashes.

3.1 Writing Functions
A function takes inputs (parameters), does work, and optionally returns a result.
fun main() {
    val result = calculateSum(10, 20)
    println("Sum is $result")
}

fun calculateSum(a: Int, b: Int): Int {
    return a + b
}

3.2 Null Safety (Kotlin's Superpower)
Null pointer exceptions crash mobile apps. Kotlin separates nullable and non-nullable types using the ? operator.
fun main() {
    var normalString: String = "Hello" // Cannot be null
    // normalString = null -> COMPILER ERROR!

    var nullableString: String? = "Android"
    nullableString = null // Allowed!

    // Safe Call Operator (?.)
    println(nullableString?.length) // Prints null safely without crashing

    // Elvis Operator (?:)
    val textLength = nullableString?.length ?: 0
    println(textLength) // Outputs 0 because nullableString is null
}

Chapter 4: Object-Oriented Programming (OOP)
--------------------------------------------------
OOP organizes code into blueprints (Classes) and physical items (Objects).

4.1 Classes, Properties, and Methods
class Player(val name: String, var level: Int) {
    // Method
    fun printInfo() {
        println("Player $name is at level $level")
    }
}

fun main() {
    val hero = Player("Mohammed", 5)
    hero.printInfo()
}

4.2 Inheritance
Inheritance lets a child class reuse code from a parent class.
open class Character(val name: String) {
    open fun attack() {
        println("$name attacks!")
    }
}

class Warrior(name: String) : Character(name) {
    override fun attack() {
        println("$name swings a massive broadsword!")
    }
}

fun main() {
    val warrior = Warrior("Arthur")
    warrior.attack()
}

Chapter 5: Introduction to XML Layouts & View Groups
Android apps build user interfaces using XML (Extensible Markup Language). A ViewGroup acts as a container organizing child views.
- LinearLayout: Arranges views linearly—either completely vertical or completely horizontal.
- ConstraintLayout: The modern, flexible standard. Views are positioned by anchoring constraints relative to each other or to the parent container.

XML Layout Sample (activity_main.xml)
<?xml version="1.0" encoding="utf-8"?>
<LinearLayout xmlns:android="http://schemas.android.com/apk/res/android"
    android:layout_width="match_parent"
    android:layout_height="match_parent"
    android:orientation="vertical"
    android:padding="16dp">

    <TextView
        android:layout_width="wrap_content"
        android:layout_height="wrap_content"
        android:text="Welcome to CodeAssist XML!"
        android:textSize="20sp"
        android:textStyle="bold" />

</LinearLayout>
* Explanation: match_parent stretches the view to fill its parent boundary, while wrap_content sizes it tightly around its contents. sp stands for scale-independent pixels (best for text sizing).

Chapter 8: The Activity Lifecycle
An Activity represents a single screen with a user interface. Activities go through different states managed by system callbacks:
- onCreate(): Called when the activity is first created. This is where you inflate your XML layout and initialize views.
- onStart(): Makes the activity visible to the user.
- onResume(): The activity enters the foreground, and the user can interact with it.
- onPause() / onStop() / onDestroy(): Handle pausing, backgrounding, and tearing down resource allocations safely.

Chapter 9: Linking XML to Kotlin (findViewById & Listeners)
--------------------------------------------------
To make buttons clickable or read text from an EditText, Kotlin code must bind directly to the XML views using findViewById.

Kotlin Activity Code (MainActivity.kt)
package com.example.myfirstapp

import android.os.Bundle
import android.widget.Button
import android.widget.EditText
import android.widget.Toast
import androidx.appcompat.app.AppCompatActivity

class MainActivity : AppCompatActivity() {

    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        
        // 1. Inflate and connect the XML layout file (activity_main.xml)
        setContentView(R.layout.activity_main)

        // 2. Link XML views to Kotlin variables using findViewById
        val etInput = findViewById<EditText>(R.id.etUsername)
        val btnSubmit = findViewById<Button>(R.id.btnSubmit)

        // 3. Set a click listener on the button
        btnSubmit.setOnClickListener {
            val enteredText = etInput.text.toString()
            
            // Show a popup toast message on screen
            Toast.makeText(this, "Hello, $enteredText!", Toast.LENGTH_SHORT).show()
        }
    }
}
* Line-by-Line Explanation:
- setContentView(R.layout.activity_main): Loads your XML layout onto the device screen.
- findViewById<EditText>(R.id.etUsername): Searches the layout hierarchy for the view matching the unique ID etUsername and casts it as an EditText.
- btnSubmit.setOnClickListener { ... }: Listens for user touch inputs on the button and executes the code block inside when tapped.
- Toast.makeText(...): Displays a brief floating notification message on the device screen.

Chapter 10: Intents (Navigating Between Screens)
--------------------------------------------------
Real Android apps have multiple screens. We transition from one Activity to another using an Intent.

Screen 1 Triggering Screen 2
// Inside MainActivity.kt when a button is clicked:
val intent = Intent(this, SecondActivity::class.java)

// Optional: Pass data across screens
intent.putExtra("USER_NAME", "Mohammed")

// Start the new activity
startActivity(intent)

Receiving Data in Screen 2 (SecondActivity.kt)
// Inside SecondActivity.kt onCreate method:
val receivedName = intent.getStringExtra("USER_NAME")
Toast.makeText(this, "Welcome back, $receivedName", Toast.LENGTH_LONG).show()
